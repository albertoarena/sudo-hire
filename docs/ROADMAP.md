# Roadmap

Planned changes after v1.0.0. Nothing here has a date. A change moves to `docs/DECISIONS.md` when it is approved and built.

## Next

- **An About section in Settings.** It shows the app version, for example "Sudo Hire 1.0.1", so the user does not need Get Info in Finder. Today the version is only in Get Info and in the diagnostic report (DECISIONS, "Release candidates and the updater").
- **One update notice, with the words of the app.** Today the update check at the start shows the notice of Electron, "sudo-hire version 1.0.1 has been downloaded and will be automatically installed on exit", next to the notice of the app, so the user gets two notices for one update. Once, in a release candidate, the notice of the app did not appear. The change: start the check without the notice of Electron, so only "Sudo Hire <version> is ready. It installs when you quit Sudo Hire." shows. The name "sudo-hire" also names the data folder, so the fix does not rename the app (DECISIONS, "The updater").
- **Keywords that match on tags need a developer title.** Today a keyword matches the title or the tags, as the source sends them. Some employers tag a job with technologies it does not use: a "Remote Office Assistant" is tagged "php". Since 1.0.2 the list row says where the keyword matched, for example 'Matched "php" in the tags from Remotive', but the job still passes. The change: when a keyword matches only in the tags, the job also needs a title that names a developer role, for example developer, engineer or programmer. A match in the title works as today. This does not stop a developer job with too many tags: a "Senior Data Engineer" tagged with about 50 technologies, "laravel" and "php" among them, still matches.
- **Two more career page providers: SmartRecruiters and BambooHR.** Today the app reads Greenhouse, Lever, Ashby, Personio and Workable. Each new provider is one more reader in the ATS reader, built like the others: a fixture from a real company, a field mapping and a check of the source terms in DECISIONS. Not decided yet. Daniele Barbaro wrote MIT-licensed connectors for both: [job-boards-smartrecruiters](https://github.com/plin-code/job-boards-smartrecruiters) and [job-boards-bamboohr](https://github.com/plin-code/job-boards-bamboohr). Their endpoint and field research can be reused, and any copied code keeps its MIT copyright notice.
- **A new company shows when it is read.** Today a company added in Settings, Companies shows "Next scan", but the career pages are one source, read at most every 6 hours. A company added just after a read waits up to 6 hours, while scans run every 5 minutes. The first scan after setup runs before the user can add a company, so the first companies always wait about 6 hours. The change: either read a new company at the next scan, or show the real time, for example "Next read at 23:55".
